# rap-auth on Cloudflare Workers

Replaces the Railway FastAPI auth server with a single Worker and a hard-coded Gmail
allowlist. **No database** — no Postgres, no Neon, no teams/memberships tables.

Why: `*.up.railway.app` is unreachable from Ethiopia (Railway's edge IP drops TCP 443),
while Cloudflare's edge is fine. The Worker doesn't just proxy — it serves the whole
sign-in flow, so Railway is out of the path entirely.

## What the desktop app needs (this is the whole contract)

| Caller | Endpoint | Response |
|---|---|---|
| `rap-web` → local `rap-server` → here | `POST /auth/verify-google-code` `{code, redirect_uri}` | `{access_token, user:{…}}` |
| `rap-server/server/config.py` | `GET /auth/public-key` | `{public_key}` |
| older web flow | `POST /auth/verify-google-token` `{token}` | `{token, user:{…}}` |
| ops | `GET /health` | `{status, allowlist_size, signing_key}` |

Takeoff/BOQ licensing rides on this: `rap-web` computes
`isEnterprise = isAuthenticated && cloudToken !== "rap-local-token"`, and only that flips
`license_tier` to `enterprise` for `/run-script` and `/api/repl`. So a real JWT from this
Worker is what unlocks the takeoff extension methods — the allowlist *is* the licence.

⚠ The JWT is signed with the **same `jwt_private.pem`** the Railway server uses, so the
public key that `rap-server` already trusts (and the bundled `server/keys/jwt_public.pem`)
keeps working. Do not generate a new key pair unless you also replace the public key in
`rap-server/server/keys/jwt_public.pem` and rebuild the app.

## Deploy (one time)

Requires a free Cloudflare account. Run from this `auth-worker/` directory.

```bash
# 1. authenticate (opens a browser)
npx wrangler login

# 2. the Google OAuth client secret (Desktop client: 367583834715-…apps.googleusercontent.com)
npx wrangler secret put GOOGLE_CLIENT_SECRET

# 3. the allowlist — comma/space separated, ~5 addresses, case-insensitive
npx wrangler secret put ALLOWED_EMAILS

# 4. the existing signing key, straight from file so it never lands in the repo
npx wrangler secret put JWT_PRIVATE_KEY < ../rap-auth-server/server/jwt_private.pem
npx wrangler secret put JWT_PUBLIC_KEY  < ../rap-auth-server/server/jwt_public.pem

# 5. ship it
npx wrangler deploy
```

`wrangler deploy` prints the URL, e.g. `https://rap-auth.<your-subdomain>.workers.dev`.

### No-npm path (recommended on a slow link)

`npm` from this connection takes ~20 s just to answer, so a `npx wrangler` download can
stall. The dashboard does everything the CLI does:

1. <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Worker** → name it `rap-auth`.
2. **Edit code**, delete the template, paste all of `src/index.js`, **Deploy**.
3. Worker → **Settings** → **Variables and Secrets**, add four **encrypted** secrets:
   `GOOGLE_CLIENT_SECRET`, `ALLOWED_EMAILS`, `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`
   (paste the PEM contents from `../rap-auth-server/server/jwt_private.pem` and
   `../rap-auth-server/server/jwt_public.pem`).
4. Add one plain-text variable: `GOOGLE_CLIENT_ID` =
   `367583834715-rlm1en39oh0sj4dq4qhtaks6j23u5q6d.apps.googleusercontent.com`.
5. **Deploy** again so the variables bind.

## Verify before touching the app

```bash
curl https://rap-auth.<your-subdomain>.workers.dev/health
# {"status":"ok","allowlist_size":5,"signing_key":true}

# the served key must be the one the app trusts (fingerprint a2e8bf23…)
curl -s https://rap-auth.<your-subdomain>.workers.dev/auth/public-key \
  | python -c "import sys,json;print(json.load(sys.stdin)['public_key'])" \
  | openssl pkey -pubin -pubout -outform DER | openssl dgst -sha256
```

⚠ **This is the one thing that could still be blocked.** Cloudflare's edge is reachable
from your line (verified), but `*.workers.dev` specifically could not be confirmed from
here without a real deployment. Run that `curl` from the machine in Ethiopia — if it
times out, tell me and we move the same Worker onto a custom domain on Cloudflare
(zero code changes, just a route) or fall back to a `*.vercel.app` front.

## Point the app at it

Three places carry the old URL:

- `rap-server/server/config.py:11` and `:72` (defaults — but an env var wins)
- `rap-web/src-tauri/src/main_bundle.rs:168` (packaged builds; needs a rebuild)
- `rap-server/server/.env` for local dev only: `AUTH_SERVER_URL=https://…workers.dev`

`rap-web/src-tauri/server-release/server/config.py` is generated by the build — don't edit it.

No Google Cloud Console change is needed: the app's OAuth redirect is
`http://127.0.0.1:<port>` (loopback), and the auth server is never in the redirect URI.

## Things that no longer exist

The old server's invite/team/member endpoints (`/teams`, `/invitations`, role switching)
are gone — deliberately, per the current product state: there is no team UI any more.
Every allowed account signs in as `owner` of a `Personal` team, exactly like the local
fallback path in `rap-server/server/api/auth_router.py`.
